# BLE 分片廣播協議

ESP32 發送端。把 Ed25519 簽章切成多個 BLE 廣播幀送出，讓附近的檢測端在不配對的情況下核對身份。檢測端程式不在這個倉庫裡。

這是試用中的發送端，尚未在實機上燒錄確認。檔案裡的 `FIXED_SEED_HEX` 仍是示例私鑰，正式使用前要換成自己的，或改成空字串讓每台板子自己產生。

## 檔案

| 檔案 | 作用 |
|------|------|
| `esp32_ble_nonce_sign_frag.ino` | 發送端韌體，協議版本 2 |
| `tools/check_protocol.py` | 在電腦上核對簽章內容、計數器和分片 |
| `upload_git.bat` | 提交並推送目前變更 |

依賴 Arduino 的 **NimBLE-Arduino** 和 **libsodium**。序列埠速率 115200。

## 燒錄前設定

改 `esp32_ble_nonce_sign_frag.ino` 開頭。程式裡有寫就用程式裡的，不寫進晶片。留空 `""` 才用晶片裡的；晶片裡也沒有，才在第一次開機產生並存入。重開機後晶片裡那組還在。

| 設定 | 作用 |
|------|------|
| `FIXED_SEED_HEX` | 64 個十六進位字就是私鑰種子。留空改用晶片裡的私鑰 |
| `MANUAL_CHALLENGE` | 有文字就用這組挑戰碼，最長 32 字節。留空改用晶片裡的；晶片裡沒有則產生 16 字節並存入 |
| `PRINT_PRIVATE_KEY` | `true` 才在開機時印出私鑰。預設 `false` |
| `CLEAR_FLASH_SECRETS` | `true` 時清掉晶片裡的私鑰、挑戰碼和計數器，然後停住。看到清除完成後改回 `false` 再上傳 |
| `CHECK_COUNTER` | `true` 每次簽名計數器加一。`false` 時計數器固定為 0，票上註明不用檢查 |

程式裡寫的值不會蓋掉晶片裡的舊紀錄。要換掉晶片裡那組，才用 `CLEAR_FLASH_SECRETS`。清除後計數器從 1 再開始，檢測端也要清掉這組挑戰碼的舊紀錄。

多台板子可以共用同一把寫在程式裡的私鑰，再用不同的挑戰碼區分。檢測端要按挑戰碼分開記計數器。

## 序列埠

開機印一次，之後每 10 秒再印：

- `[PUB]` 公鑰，給設定人員登記
- `[CHAL]` 目前使用的挑戰碼
- `[CTR]` 最近一次簽出去的計數器，以及私鑰和挑戰碼是來自程式還是晶片

`PRINT_PRIVATE_KEY` 為 `true` 時，開機另印一行 `[PRIV]`。抄完後改回 `false` 再燒錄。

## 簽章內容

簽進去的位元組，大端序：

```
[1B flags] [4B counter] [1B challenge_len] [challenge] [32B nonce]
```

後面再接 64 字節 Ed25519 簽章。這整段才是被分片廣播的本體。

`flags` 的 bit0 為 1 時，檢測端應拒絕不大於上次的計數器。為 0 時是測試票，可以不檢查計數器。

預設挑戰碼 `test` 時，本體為 106 字節。

## 幀格式

每一幀：

```
[1B Length] [1B AD Type] [2B Seq] [Data] [1B CRC8]
```

`Length` 是它後面的位元組數。整幀最長 31 字節。數據幀每次最多帶 26 字節。CRC8 多項式 `0x31`、初值 `0x00`，計算範圍是序號加數據。

| AD 類型 | 含義 |
|---------|------|
| `0xDD` | 宣告幀，24 字節元資料 |
| `0xDE` | 中間數據幀 |
| `0xDF` | 最後一個數據幀 |

宣告幀元資料：

| 位元組 | 內容 |
|--------|------|
| 0–1 | 本體長度，uint16 大端 |
| 2 | 數據幀數量，不含宣告幀 |
| 3 | 協議版本，目前是 2 |
| 4 | flags |
| 5 | 挑戰碼長度 |
| 6–23 | 填 0 |

同一張票的序號連續。下一張從上一張最後一個序號之後繼續。序號是 16 位，加到放不下時從 0 再開始。幀與幀間隔 120 毫秒。中間任何一幀沒收到，這一張票就組不齊，程式不會補送同一張。

## 檢測端要做的事

1. 用宣告幀的長度和幀數，按序號把數據幀拼成完整本體。
2. 每幀先對 CRC。
3. 用事先登記的公鑰驗證簽章。被簽的是本體裡簽章之前的全部位元組。
4. 挑戰碼必須和登記的那組相同。
5. `flags` bit0 為 1 時，計數器必須大於這組挑戰碼上次接受的值，然後記住新值。

公鑰和挑戰碼從序列埠抄走再登記。不要信任廣播裡臨時出現的新公鑰。兩個互不通知的檢測端仍會各收一次同一張票，它們要共用「這組挑戰碼已用到哪個計數器」。

## 電腦上的檢查

已在開發機上跑過 `tools/check_protocol.py`，核對的是算法，不是藍牙：

- 簽章覆蓋 flags、計數器、挑戰碼和隨機數；改一個位元組就驗失敗
- 預設本體 106 字節，6 幀，每幀不超過 31 字節，CRC 正確，能拼回原樣
- 序號 250–255 的下一張進到 256，兩張票的序號不重疊
- 計數器 1 到 8192，模擬重開機後從 8193 繼續，不重複

```bash
python tools/check_protocol.py
```

藍牙廣播有沒有被另一台裝置收到，要有 ESP32 實機才能確認。
